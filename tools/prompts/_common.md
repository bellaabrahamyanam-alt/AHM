# Common rules for every agent (read after your role file)

1. English only. First line of every answer: `Domain: <your domain>`. Short and concrete answers; no pasted files or test output.
2. Read `context/<domain>.md` and ONLY the files it lists. If `tools/prompts/domain/<domain>.md` exists, read it too (domain notes; its "Git delivery" part is replaced by this file). Then read the task spec the owner names (`tasks/NNN-*.md`). Do only what the task asks.
3. One task = one branch `<domain>/<task>` = one merge request (MR) on GitLab, project `bellaabrahamyan.am/ahm` (id 88632181), trunk branch `master`. Never push or commit to `master`. The `-tdd` agent creates the branch, the `-dev` agent continues on it. Two ways to get commits to GitLab:
   - **With git access** (your own computer, Claude Code in a terminal): `git fetch origin master && git checkout -b <domain>/<task> origin/master`, commit, `git push -u origin <branch>`.
   - **Without git access** (the Claude cloud session: `git push`/`git fetch` fail with `CONNECT tunnel failed, 403`): use the GitLab tools. They are deferred, so first load them with ToolSearch (`select:mcp__gitlab__add_branch,mcp__gitlab__add_commit,mcp__gitlab__save_merge_request,mcp__gitlab__get_merge_request,mcp__gitlab__get_pipeline,mcp__gitlab__get_job`). Create the branch with `add_branch` (`branch`, `ref: master`) and commit with `add_commit` (`branch`, `commit_message`, `actions`): at most 100 file actions per call, `update` with `old_str`/`new_str` for edits, `create` with `content` for new files, `delete` for removals. Run the tests on your local copy first; the commit message rules of rule 4 apply to every `add_commit`.
4. Commits read `<type>: <what>` (`test:`, `feat:`, `fix:`, `docs:`). End each commit message with the Co-Authored-By and Claude-Session lines your environment gives you.
5. Change only your domain's files (table: `tools/domains.json`). Check before pushing: `node tools/ci-check-pr.js <branch> origin/master`. Anything outside your domain: write `requests/<from>-to-<to>-NNN-<name>.md` (fits the interface) or `proposals/NNN-<name>.md` (changes an interface) and stop that part. Interfaces and shared files change only with the owner's approval.
6. Log the change in `changes/<domain>.md` in the same merge request (date, what, why, files, how to verify, follow-ups).
7. Tests, output always cut: `php tests/php/run.php 2>&1 | tail -15`, `php tests/data/run.php 2>&1 | tail -15`, `node tests/js/run.js 2>&1 | tail -15` (`--no-browser` is quicker). Never weaken, delete or edit a test you did not write for this task.
8. Open the merge request with `save_merge_request` (`project_id: bellaabrahamyan.am/ahm`, `source_branch`, `target_branch: master`, `title: "<type>: <what>"`, `description` = the summary using `.gitlab/merge_request_templates/Default.md`, `squash: true`, `remove_source_branch: true`). `gh` and GitHub are not used any more.
9. Check CI: `get_merge_request` (`include: ["pipelines"]`) every 45 s (up to 10 min) until the newest pipeline is not `created`, `pending` or `running`. It must be `success`. On `failed` read `get_pipeline` (`include: ["jobs"]`, `job_status: failed`) and `get_job` (`include: ["log"]`, `from: "end"`, `byte_limit: 6000`), fix on the same branch, push again.
10. **Only `gatekeeper` merges.** `-dev` agents fix red checks on the same branch, then report "MR !n ready for gatekeeper" and stop. Nobody else merges, ever.
